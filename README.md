# BTC Signal Bot 🤖

Telegram-бот, который описывает структуру рынка BTC/USDT по нескольким
таймфреймам: зоны старших ТФ (Smart Money), каскад шумоподавления, ведение
прогнозов по этапам и измерение на истории с учётом комиссий.

> ⚠️ **Подтверждённой торговой модели здесь нет.** Гипотезы H1/H2 отклонены,
> confluence score никогда не был валидирован, а волатильностная модель
> поставлена на паузу вердиктом C4.3c: ridge проиграл по MAE и скользящему
> среднему, и константе. Всё, что бот показывает, — описание текущей
> структуры, а не рекомендация. Единственные фактические результаты — в
> `/journal` по закрытым сделкам.
>
> Не является финансовой рекомендацией. Используйте на свой риск.

## Потоки анализа

По умолчанию активны три профиля; `bounce` выключен (`ENABLE_BOUNCE_PROFILE`).

| | 📊 Свинг | 🌊 Позиционный | ⚡ Интрадей |
|---|---|---|---|
| Вход | 4H | 4H | 15m |
| Тренд (HTF-фильтр) | 1D | 1D | 4H |
| Зоны (OB/FVG/цели) | 12H + 6H | 1D + 12H | 4H + 2H + 1H |
| Согласие ТФ | 1H/4H/12H/1D | 4H/12H/1D | 15m/1H/4H |
| Cooldown | 8 ч | 24 ч | 2 ч |
| Анализ | каждые 4 ч | каждые 4 ч | каждые 15 мин |
| Горизонт прогноза | 1-14 дней | 1-6 недель | до 24 часов |

Параметры профилей: `signal_engine/profiles.py` (цели/стоп настраиваются через
`SWING_TARGETS`, `POSITION_TARGETS`, `INTRADAY_TARGETS`, `*_ATR_MULT`).
Каждый поток запускается по закрытию своей входной свечи (`scheduler.py`).

## Каскад шумоподавления

Внутренняя механика отбора. Она уменьшает поток сообщений, но **не является
проверенным источником прибыли** — ни один из уровней ниже не прошёл
walk-forward-валидацию.

1. **Режим рынка** — `signal_engine/regime.py` задаёт веса категорий.
2. **HTF-фильтр** — сигнал против старшего тренда блокируется полностью.
3. **Confluence Score** — очки в 5 категорий (тренд/импульс/объём/структура/макро);
   Smart-Money факторы весят больше: HTF Order Block +3, снятие ликвидности +3,
   FVG +2, premium/discount +2, разворот на экстремуме +2/+3.
   Не отображается пользователю (D1.2): число не откалибровано.
4. **Разнообразие** — минимум 3 разные категории (`MIN_DIVERSE_CATEGORIES`).
5. **Конфликты** — при вероятном свипе ликвидности вход откладывается.
6. **No-trade gate и вето** — `no_trade_gate.py`, `vetoes.py`: плохой R:R,
   аномальная волатильность, истощение тренда.
7. **Согласие ТФ** — направленный множитель уверенности (4/4 → ×1.2, против → ×0.7).
8. **Cooldown/дедуп** — по каждому потоку отдельно.
9. **Дневной лимит** — жёсткий cap `MAX_SIGNALS_PER_DAY` (по таймфрейму, скользящие 24 часа); сигналы сверх лимита сохраняются в журнал (/signal), но не отправляются.
10. **Свежесть решения** — если от закрытия входной свечи прошло больше
    `max_decision_delay_seconds`, ENTER понижается до WAIT (`pipeline.py`).

Все гейты описаны как контракт в `contracts/final_gate.py` — он не выполняет
проверки, а фиксирует их список и сверяет фактическое решение с ожидаемым.

Классификация: score ≥8 (`SCORE_ALERT_MIN`) → авто-уведомление;
5-7 (`SCORE_JOURNAL_MIN`) → журнал (`/signal`); <5 → игнор.

## Команды

| Команда | Действие |
|---|---|
| `/market` | Цена, funding, L/S, open interest, Fear & Greed одним экраном |
| `/levels` | Ближайшие S/R, OB/FVG с HTF, Volume Profile, ликвидации, EMA, вывод |
| `/funding` | Деривативы: funding rate, long/short ratio |
| `/reversal` | Дно/пик: истощение тренда сразу по 1H/4H/12H/1D (≥2 ТФ = подтверждение) |
| `/position` | Прогноз для спота (структура 1D/12H, горизонт недели) |
| `/signal`, `/intraday` | Прогноз для фьючерсов: свинг / интрадей |
| `/journal` | Реальный винрейт и R по закрытым сделкам |
| `/backtest [swing\|intraday\|position]` | Перебор порогов на истории, NET (с комиссиями), проекция %/мес — измерение, не рекомендация |
| `/setalert <цена>`, `/alerts`, `/delalert` | Ценовые алерты по уровню |
| `/status`, `/testalert` | Здоровье бота и проверка канала уведомлений |
| `/ask <вопрос>` | Вопрос к Claude с рыночным контекстом (любой текст = /ask) |
| `/start`, `/help` | Меню кнопок и полный список команд |

`/start`, `/delalert` и `/testalert` зарегистрированы как обработчики, но
намеренно не попадают в «/»-меню Telegram (`BOT_COMMANDS`).

### Меню

Интерфейс — кнопки (reply-клавиатура + inline-меню), появляются после `/start`.
Три раздела (D1.3):

- **📊 Анализ рынка** → общий анализ, уровни, funding, reversal
- **🔮 Прогноз** → спот, фьючерсы-свинг, фьючерсы-интрадей
- **📓 Торговый журнал** → открытые прогнозы, история, статистика

Экран прогноза называет свой рынок (`СПОТ` / `ФЬЮЧЕРСЫ · СВИНГ` /
`ФЬЮЧЕРСЫ · ИНТРАДЕЙ`). Спот рендерится отдельно: без размера позиции и
риска в процентах — на споте нет маржи, поэтому эти числа неприменимы.

## Ведение сделок

Каждый отправленный сигнал ведётся как позиция:
`TP1 достигнут → стоп в безубыток → TP2 (win) / возврат к БУ (0R) / стоп (−1R)`,
с уведомлением на каждом этапе. Исходы проверяются на **родном таймфрейме**
сделки каждые 15 минут; статистика — в `/journal`.

## Деплой (Railway)

1. Подключить репозиторий + плагин **PostgreSQL** (`DATABASE_URL` через
   `${{Postgres.DATABASE_URL}}`).
2. Обязательные переменные: `TELEGRAM_BOT_TOKEN`, `ANTHROPIC_API_KEY`,
   `TELEGRAM_ALERT_CHAT_IDS` (chat_id получателя).
3. Безопасность: `TELEGRAM_ALLOWED_CHAT_IDS` — кто вообще может писать боту
   (по умолчанию = получатели алертов; чужие отклоняются).
4. Старт в **`DRY_RUN=true`**: анализ идёт, уведомления не шлются. Для
   manual-only Telegram-сигналов без авто-сделок можно включить
   `SEND_DRY_RUN_ALERTS=true`. Проверить `/status` и `/testalert`, затем
   `DRY_RUN=false` для LIVE-уведомлений.
5. Источник данных: `EXCHANGE=auto` (Bybit↔Binance c автофейловером при 451).

Полный список переменных — в `.env.example`. Все внешние источники, кроме
биржи/Telegram/Anthropic, опциональны (graceful degradation).
